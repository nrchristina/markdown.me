# Markdown.me — план реализации

Источник требований: [`docs/spec.md`](spec.md). Подпись и TCC: [`docs/macos-signing-tcc.md`](macos-signing-tcc.md).
Трекер задач: Notion, база **Markdown.me — Task list** —
<https://app.notion.com/p/c54889d0f5bd467e955315e53292b153>. У каждой задачи там есть
«Что сделать», «Не входит» и «Готово, когда». Здесь — сквозные решения, на которые
задачи опираются, и индекс задач.

## Архитектурные решения

Меняются только осознанно: правкой этого файла в том же PR.

| Тема | Решение | Почему |
|---|---|---|
| Стек | Swift 6, SwiftUI + AppKit, macOS 14+ | ТЗ §12; редактору нужен NSTextView |
| Сборка | SwiftPM + `scripts/build-app.sh`, без Xcode-проекта | всё в тексте, удобно для Claude; схема подписи из `macos-signing-tcc.md` уже отлажена |
| Модули | `MarkdownCore` (чистая логика + cmark-gfm) и `MarkdownMe` (приложение) | логику можно тестировать где угодно, `swift test` быстрый |
| Bundle ID | литерал, выбирается один раз в MD-1 и не меняется | к нему привязаны TCC, Sparkle и UserDefaults |
| Ресурсы | копирует скрипт в `Contents/Resources`, код берёт из `Bundle.main`; `Bundle.module` не используется | accessor SwiftPM ищет бандл в корне `.app`, это ломает подпись |
| Источник правды | markdown-строка в NSTextStorage; оба режима показывают одно и то же хранилище | переключение режима никогда не меняет файл; нет потерь при конвертации туда-обратно |
| Режим «Markdown» | raw-текст + подсветка синтаксиса, SF Mono | ТЗ §8 |
| Режим «Текст» | live preview: маркеры скрыты (null-глифы TextKit 1), кроме строки с курсором | WYSIWYG-ощущение без отдельной модели документа |
| Текстовый движок | NSTextView на TextKit 1, созданный явно | скрытие глифов через `NSLayoutManagerDelegate` есть только в TextKit 1 |
| Парсер | cmark-gfm напрямую (`swiftlang/swift-cmark`), GFM: таблицы, зачёркивание, задачи | swift-markdown поверх того же cmark тратит 235 мс на 1 МБ только на своё дерево; у инлайн-элементов cmark местами ошибается в позициях — `MarkdownCore` их исправляет (`InlinePositions.swift`); UTF-8 → UTF-16 обязательно |
| CI | GitHub Actions: `swift test` для `MarkdownCore` на Linux на каждый push | облачные сессии не могут собрать приложение, но логику проверить могут |
| Форматирование | чистые функции `(text, selection) → TextEdit` в MarkdownCore: `FormattingCommand.edit(in:selection:syntax:)` для тулбара и меню, `ListEditing` для Enter, Tab, ⇧Tab и чекбоксов. Одна минимальная правка в UTF-16; `nil` — править нечего (у `ListEditing` — клавиша не обработана) | одинаково в обоих режимах, покрыто unit-тестами; одна правка — один шаг undo |
| Цвет и размер | inline HTML `<span style="…">`, именованная палитра, ступени размера | в Markdown этого нет; другие редакторы span показывают, GitHub просто выкинет style |
| Файлы | без песочницы, прямые URL; workspace — папка; явное сохранение ⌘S | не App Store (ТЗ §1) |
| PDF | markdown → HTML + print CSS → offscreen WKWebView → NSPrintOperation | нормальная пагинация без своего движка вёрстки |
| Локализация | `en.lproj` (база) + `ru.lproj`; переключатель через `AppleLanguages` + перезапуск | тогда и системные меню и панели тоже переводятся |
| Обновления | Sparkle 2, EdDSA; DMG и `appcast.xml` в GitHub Releases; `SUFeedURL` = `…/releases/latest/download/appcast.xml` | ТЗ §2 |
| Дистрибуция | Developer ID Application + hardened runtime + нотаризация + staple; DMG | ТЗ §1 |
| Сайт | статический `site/` на Vercel; кнопка → `…/releases/latest/download/MarkdownMe.dmg` | ТЗ §4 |
| Шорткаты | как в ТЗ §9 + ⌘/ переключение вида (как в Typora), ⌃⌘S сайдбар, ⌘⇧O открыть папку; ⌘E отобран у «Use Selection for Find» | |

Вне MVP, записано явно: рендер таблиц в режиме «Текст» (таблицы показываются
моноширинным исходником), drag & drop и вставка картинок из буфера, автосохранение, CI-релизы.

## Что нужно решить до старта (не Claude)

- **Bundle ID** — нужен в MD-1, например `com.<имя>.markdownme`.
- **Apple Developer Program** (MD-20) — оформить заранее, проверка бывает до 48 часов.
  Для dev-сборок хватит сертификата Apple Development.
- **Публичность репозитория** — ассеты релизов приватного репо без авторизации не скачать,
  поэтому Sparkle и кнопка на сайте работать не будут. Либо этот репо станет публичным,
  либо релизы уйдут в отдельный публичный репо.

## Как работать с задачами

- **Одна задача = одна сессия Claude Code = одна ветка и PR.** Задачи нарезаны так, чтобы
  влезть в одно 5-часовое окно лимита на Opus xHigh с запасом на тесты и проверку.
  Если сессия не укладывается, задачу делят в Notion на две, а не продолжают вслепую.
- **Почти всё делается на Mac, в локальном Claude Code.** Облачная сессия работает в Linux
  и не может собрать и запустить macOS-приложение. В облаке можно делать только задачи с
  пометкой «облако подходит» (чистая логика MarkdownCore и сайт).
- Шаблон запроса на старт сессии:

  > Задача MD-N: <ссылка на страницу в Notion>. Прочитай `CLAUDE.md` и `docs/PLAN.md`,
  > потом страницу задачи. Сделай то, что в «Что сделать», проверь всё из «Готово, когда»,
  > закоммить в новую ветку и открой PR. Если по ходу меняется архитектурное решение —
  > обнови таблицу в `docs/PLAN.md`.

- Готово = `swift test` зелёный, `scripts/build-app.sh` зелёный (после MD-1),
  `scripts/lint-tokens.sh` зелёный (после MD-2), пункты «Готово, когда» проверены,
  скриншоты UI-изменений в PR, статус в Notion переведён в Done.

## Порядок

Критический путь: MD-1 → MD-2 → MD-3 → MD-4 → MD-6 → MD-9 → MD-10 → MD-11 →
(MD-13 → MD-14) → MD-18 → MD-21 → MD-22 → MD-23 → MD-24 → MD-26.

Что можно делать параллельно, не блокируя путь:

- MD-5 и MD-7 (чистая логика) — сразу после MD-1, в том числе в облаке.
- MD-20 (Apple Developer Program) — начать в первый же день, это ожидание, а не работа.
- MD-16, MD-17 — как только готов MD-8.
- MD-25, MD-29 (сайт и тексты) — в любой момент после MD-2.
- MD-21…MD-23 можно начать раньше конца v0.3: пайплайну нужен только работающий `.app`.

Самый рискованный пункт — MD-9 (скрытие маркеров в NSTextView). В задаче есть стоп-правило:
если подход не работает за первый час, сессия останавливается и описывает альтернативу.
Если MD-9 провалится, пересматриваются MD-10 и MD-11.
