# macOS: чтобы приложение открывалось и не теряло разрешения при пересборке

Контекст, добытый отладкой вживую на проекте FlyTranslate (SwiftPM →
`.app`, меню-бар приложение, которому нужен Accessibility). Переносится в
любой проект, который собирает `.app` руками, без Xcode-таргета.

## Главный факт

macOS выдаёт разрешения (Accessibility, Screen Recording, Input Monitoring,
Automation) не пути и не имени приложения, а **идентичности кода**:

```
CFBundleIdentifier  +  подпись кода (designated requirement)
```

База TCC хранит запись по этой паре. Если любая половина поменялась — запись
от предыдущей сборки к новой не относится. Коварство в том, что **галочка в
System Settings остаётся включённой**: пользователь её видит, а
`AXIsProcessTrusted()` возвращает `false`. Приложение запускается, выглядит
рабочим и молча ничего не делает.

Отсюда всё остальное: обе половины идентичности должны быть стабильными
между сборками.

## Половина 1: подпись

`swift build` сам ставит на бинарник ad-hoc-подпись от линкера. Она
привязана к содержимому — меняется при каждой пересборке. Значит ad-hoc
непригоден: разрешение слетает после каждого билда.

Нужен настоящий сертификат. **Сначала проверить, что уже есть** — если стоял
Xcode, сертификат уже лежит в связке ключей:

```bash
security find-identity -v -p codesigning
```

Типичный ответ:

```
1) F6F3EF50... "Apple Development: you@example.com (N623NHNZLP)"
   1 valid identities found
```

Этого достаточно. `Apple Development` привязан к Apple ID и team id, и при
продлении сертификата designated requirement остаётся тем же — разрешение
переживает и продление.

Если список пуст — создать самоподписанный один раз: Keychain Access →
Certificate Assistant → Create a Certificate → Identity Type **Self Signed
Root**, Certificate Type **Code Signing** (по умолчанию там S/MIME, это
частая ошибка).

Дальше — в `~/.zshrc`, а не только в текущей оболочке:

```bash
export CODESIGN_IDENTITY="Apple Development: you@example.com (N623NHNZLP)"
```

> Половина отладки ушла именно на это: переменная указывала на сертификат,
> которого не существовало. `codesign` падал с `no identity found`, скрипт
> умирал по `set -e` до подписи, а собранный бандл оставался с
> ad-hoc-подписью линкера и выглядел как собранный.

## Половина 2: signing identifier

Если не задать явно, `codesign` выводит идентификатор сам — и для бандла,
который он не распознал, берёт сгенерированный линкером
`MyApp-5555494430f733abd48f39a8b957b73f49b04547`. Он завязан на UUID
сборки, меняется каждый билд, и `tccutil` не умеет обратиться к нему по
имени, то есть протухшую запись даже не сбросить.

Поэтому идентификатор прибивается гвоздями:

```bash
codesign --force --options runtime \
    --identifier "com.example.myapp" \
    --sign "${CODESIGN_IDENTITY}" "${APP_DIR}"
```

Читать его лучше из уже собранного `Contents/Info.plist`, а не хардкодить
второй раз:

```bash
BUNDLE_ID="$(/usr/libexec/PlistBuddy -c "Print :CFBundleIdentifier" \
    "${APP_DIR}/Contents/Info.plist")"
```

Если plist генерируется из шаблона (подстановка версии, коммита) — важен
порядок: сначала сгенерировать plist в бандле, потом читать из него.
`CFBundleIdentifier` шаблонизировать нельзя, он должен быть литералом.

## Проверки, без которых поломка молчит

Это главный урок: **все три способа сломать идентичность проходят без
ошибок и выясняются только мёртвым приложением.** Поэтому сборка должна
падать сама.

```bash
# 1. Бандл вообще подписан? Подпись бандла всегда создаёт этот файл.
#    Без него `codesign -dv` показывает подпись внутреннего бинарника
#    от линкера — и это выглядит как нормальный вывод с Identifier и CDHash.
if [[ ! -f "${APP_DIR}/Contents/_CodeSignature/CodeResources" ]]; then
    echo "ERROR: bundle was never signed" >&2
    exit 1
fi

# 2. Идентификатор тот, который ожидаем?
SIGNED_ID="$(codesign -dv "${APP_DIR}" 2>&1 | sed -n 's/^Identifier=//p')"
if [[ "${SIGNED_ID}" != "${BUNDLE_ID}" ]]; then
    echo "ERROR: signed as '${SIGNED_ID}', expected '${BUNDLE_ID}'" >&2
    exit 1
fi
```

Плюс печатать `Identifier` и `CDHash` в вывод сборки: дрейф подписи тогда
виден глазами, без раскопок.

## Ручная диагностика

```bash
codesign -dv --verbose=4 MyApp.app 2>&1 | \
    grep -E 'Identifier=|Signature=|Authority=|Info.plist=|TeamIdentifier='
```

Здорово выглядит так:

```
Identifier=com.example.myapp
Authority=Apple Development: you@example.com (N623NHNZLP)
Authority=Apple Worldwide Developer Relations Certification Authority
Authority=Apple Root CA
TeamIdentifier=N623NHNZLP
```

Признаки поломки:

| В выводе | Что это значит |
|---|---|
| `Identifier=MyApp-5555…` | идентификатор от линкера, меняется каждый билд |
| `Signature=adhoc` | подпись меняется каждый билд |
| `Info.plist=not bound` | бандл не подписан; показана подпись внутреннего бинарника |
| `TeamIdentifier=not set` | то же — настоящей подписи нет |
| нет `Contents/_CodeSignature/` | подтверждение: бандл не подписан |

Для подписанного бандла вместо `Info.plist=not bound` печатается
`Info.plist entries=N` — то есть отсутствие строки «not bound» и есть
правильный исход.

## Сброс протухшей записи TCC

Переключить галочку в System Settings **недостаточно** — запись от старой
подписи остаётся в базе.

```bash
tccutil reset Accessibility com.example.myapp
```

Если старая сборка была зарегистрирована под идентификатором линкера, по
имени её не адресовать — один раз сбросить сервис целиком (побочно слетит
Accessibility у Raycast, Rectangle и прочих, их включить заново):

```bash
tccutil reset Accessibility
```

Затем запустить приложение и выдать доступ заново.

## Контрольная проверка, что вылечено

Именно эта последовательность, а не «сейчас работает»:

1. Выдать доступ, убедиться, что приложение видит разрешение.
2. **Пересобрать** и запустить снова.
3. Разрешение должно остаться выданным.

Пункт 3 — весь смысл упражнения. До починки на этом месте было
`NOT GRANTED` при включённой галочке.

## Мелочи, которые помогают

- **Показывать статус разрешения в UI приложения**, обновляя при каждом
  открытии меню (`AXIsProcessTrusted()`), а не только при запуске:
  разрешение отзывается на ходу. Без этого индикатора отладка вслепую.
- **Штамповать в Info.plist версию, коммит и ветку** и показывать в UI.
  Отдельная ловушка того же класса: собрали непритянутый чекаут, всё
  выглядит рабочим, нового кода в бинарнике нет.
- `--deep` Apple считает устаревшим. Для одного бинарника без вложенных
  фреймворков он безвреден; при вложенном коде правильнее подписывать
  изнутри наружу отдельными вызовами.
- Клиенту Accessibility API никакие entitlements не нужны — только подпись
  и разрешение TCC. `--options runtime` (hardened runtime) при этом
  включать можно.

## Чего мы НЕ касались

Gatekeeper и карантин. Локально собранный `.app` не получает атрибут
`com.apple.quarantine`, поэтому «не открывается, повреждено» мы не видели.
Если бандл будет передаваться на другую машину — это отдельная тема
(notarization или `xattr -d com.apple.quarantine`), в этой отладке её не
было.
