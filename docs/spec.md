# Техническое задание: Markdown-редактор для macOS

## 1. Дистрибуция
- Приложение НЕ публикуется в Mac App Store
- Распространяется как самостоятельный установочный файл (.dmg/.pkg) для скачивания напрямую с сайта
- Нотаризация Apple (notarization) + подпись разработчика (Developer ID) для обхода блокировки Gatekeeper

## 2. Автообновления
- Механизм: **Sparkle** (open-source фреймворк для автообновлений вне App Store, стандарт для Mac-приложений)
- Хостинг билдов и appcast.xml (манифест версий): **GitHub Releases** — бесплатно, не требует своего сервера
- Приложение периодически проверяет appcast, при наличии новой версии — предлагает скачать и установить (с подтверждением пользователя)
- Обновления должны быть подписаны (EdDSA-ключ Sparkle)
- В будущей Windows-версии — аналогичный подход (Tauri Updater или Velopack, в зависимости от выбранного стека), билды тоже через GitHub Releases

## 3. Монетизация
- MVP: полностью бесплатно, без монетизации
- В будущем: Buy Me a Coffee или небольшой one-time payment
- Архитектурно: не требовать аккаунт, лицензионный ключ или онлайн-активацию на старте
- Оставить место в UI (About/Settings) под будущую ссылку поддержки

## 4. Сайт / страница загрузки
- Хостинг: **Vercel**
- Простой лендинг с кнопкой «Download for Mac», скриншотами, описанием фич
- Билды (.dmg/.pkg) на лендинге не хранятся — ссылка ведёт на GitHub Releases
- В будущем: место под serverless-эндпоинт для проверки оплаты/лицензии (Stripe/Buy Me a Coffee webhook), когда появится монетизация

## 5. Визуальный стиль

### Референс-направление (единое, не микс из разных стилей)
Холодный тёмно-серый фон с синим подтоном (не чистый чёрный и не нейтральный серый). Разделители — тонкие hairline-линии, почти незаметные; структура держится на отступах, а не на рамках и не на тенях у карточек. Один сдержанный акцентный цвет (насыщенный синий), используется точечно — на активных состояниях, кнопках, тогглах — и нигде больше. Никаких градиентов, радужных обводок и декоративных элементов. Иерархия строится типографикой (жирность, размер) и spacing, а не цветом. Плотность информации выше, чем в «дышащих» consumer-приложениях — интерфейс рассчитан на рабочий инструмент, а не на лендинг.

Явно избегать: голубой/индиго-градиенты, скругления «на всём подряд», drop shadow на карточках, шрифт Inter по умолчанию без явного выбора, tracked-заглавные лейблы, нумерацию вида 01/02/03 — это распознаваемые AI-дефолты.

### Тема
- Светлая/тёмная, синхронизация с системной темой + ручное переключение

## 6. Сложность интерфейса
- Максимально просто, без визуального шума
- Минимум настроек и панелей по умолчанию

## 7. Дизайн-система (токены)
Перед генерацией UI-кода нейронка должна построить единую систему значений — не подбирать пиксели по ходу дела для каждого элемента отдельно.

- **Типографическая шкала** — построить по модулярной сетке (например, коэффициент 1.25 или 1.333), не произвольные значения вроде «тут 13px, тут 12, тут 11». Зафиксировать 5-6 уровней (заголовок/подзаголовок/body/small/caption) с чёткими весами шрифта под каждый уровень.
- **Цветовые роли** — именованные семантические токены с точными hex-значениями (не «на глаз»): `background`, `surface`, `border-hairline`, `text-primary`, `text-secondary`, `accent`, `accent-hover` — отдельный набор hex для светлой и для тёмной темы.
- **Spacing-шкала** — на базовой единице (4px или 8px), кратные значения вместо случайных отступов.
- **Радиусы скругления и толщина линий** — тоже как токены с 2-3 фиксированными значениями, не «на глаз» под каждый компонент.
- Всё собрать в единый файл констант (для Swift — `DesignTokens.swift`), на который ссылается весь UI-код, без хардкода значений внутри отдельных вьюх.

## 8. Структура интерфейса

### Сайдбар (слева)
- Дерево файлов/директорий (file explorer)
- Открытие директории как workspace/vault
- Переключение между открытыми файлами
- Сворачивание/разворачивание сайдбара

### Основная область (справа)
- Toolbar сверху
- Справа от toolbar — переключатель вида (таб): «Текст» (rich preview) / «Markdown» (raw-разметка)
- Ниже — рабочая поверхность с текстом документа

### Toolbar — инструменты форматирования
- Жирный, курсив, зачёркнутый
- Заголовки (H1–H6, минимум H1–H3)
- Цвет текста
- Размер текста
- Списки (маркированные/нумерованные), чек-листы
- Цитаты, код (инлайн и блоки)
- Вставка ссылок, изображений
- Горизонтальный разделитель

## 9. Горячие клавиши
- ⌘B — жирный
- ⌘I — курсив
- ⌘⇧X — зачёркнутый
- ⌘1 / ⌘2 / ⌘3 — заголовки H1/H2/H3
- ⌘K — вставить ссылку
- ⌘S — сохранить
- ⌘E — экспорт в PDF
- Переключение вида «Текст/Markdown»

## 10. Локализация
- Английский язык интерфейса по умолчанию
- Переключение на русский язык в настройках

## 11. Сохранение и экспорт
- Сохранение как .md файл (нативный формат)
- Экспорт в PDF

## 12. Платформы
- **MVP**: macOS, нативно на Swift/SwiftUI
- **В будущем**: Windows-версия
  - Стек — открытый вопрос: нативный C#/WinUI либо Tauri/React для общей кодовой базы с расчётом на кроссплатформенность
